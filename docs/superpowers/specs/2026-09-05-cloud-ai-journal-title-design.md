# 云端笔记 AI 标题无阻塞生成设计

## 目标

笔记正文保存必须立即完成，不等待 AI。新建笔记和编辑历史伪标题（`Untitled` 或 `YYYY-MM-DD HH:MM`）后，标题在后台尽快生成，并在完整生成后一次性更新；不得出现临时标题、整页刷新、白屏或覆盖用户手写标题。

## 已确认根因

- `JournalService._maybe_generate_ai_title` 在 Vercel 中同步执行模型请求，保存延迟等于模型调用及重试延迟。
- 前端 `scheduleTitleRefresh` 固定等待 4 秒后失效全部 journal 查询。它既不能保证恰好等到标题，又会触发多个列表重新请求。
- 当前编辑草稿是本地 state，同一笔记 ID 的查询缓存变化不会自动同步标题，因此单纯刷新列表也不能可靠更新编辑器。

## 设计

### 保存与生成解耦

创建和更新接口只保存正文，不调用模型。新增 `POST /api/journals/{journal_id}/generate-title`：仅当目标仍是伪标题且正文非空时生成标题，并返回最新 `JournalResponse`。请求直接调用快速标题模型，因此没有队列调度延迟；它与保存请求分离，所以不会阻塞保存体验。

### 完整标题一次性出现

前端收到保存结果后立即结束“保存中”状态。如果返回的标题仍是伪标题，则在后台调用标题接口。页面继续显示正文，时间标题和 `Untitled` 继续沿用现有隐藏规则；不生成临时标题，也不流式展示半截标题。

### 并发和用户编辑优先

前端按 journal ID 去重进行中的生成请求。后端生成开始时记录伪标题值，模型返回后以“用户 ID + journal ID + 原标题仍未变化”为条件原子更新。若用户期间手动填写标题，条件更新失败并返回用户的最新版本，AI 结果不会覆盖用户输入。

### 精准更新，不刷新页面

标题接口返回后，前端只修改该 journal 在 detail、list 和 lite 查询缓存中的记录，并在当前编辑器仍打开同一笔记且标题仍为伪标题时更新 draft.name。删除固定 4 秒定时器和 `journals.all` 全量失效。标题可使用轻微淡入，但不改变页面加载状态。

### 失败恢复

标题失败不影响已经保存的正文，界面保持现状且不显示阻断错误。下一次编辑同一伪标题笔记时可再次触发。模型请求采用快速主通道；备用通道属于标题请求自身，不回流阻塞保存请求。

## 验收标准

- 云端新建或编辑伪标题笔记时，保存响应不包含模型等待时间。
- 标题生成完成后，无需手动刷新即可出现在卡片与当前编辑器中。
- 页面不出现空白帧，已有列表、滚动位置和编辑内容保持稳定。
- 生成期间手动修改标题，最终保留用户标题。
- 同一笔记连续失焦不会产生并行标题请求。
- AI 失败不影响正文保存，并允许后续重试。
